# Breadverse 募資/行銷頁面架構

> 依課程的募資產品行銷頁框架填寫。Breadverse 是**免費的數位產品**（無實體、無定價、目前為個人專案），
> 因此部分商業化欄位標示「不適用」；需要真實受測者/市調的欄位標示「從缺」。
> 產品理念的完整版見 `README.md` 與 `CLAUDE.md` 的 Product philosophy。

## 0區 — 競爭分析

### 競品分析 competing product analysis

（各類別一張代表圖 → 圖從缺，先以文字命名定位）

| 類別命名 | 代表 | 他們是什麼 | 他們缺什麼 |
|---|---|---|---|
| **「秤」— 工具型計算器** | 各式 baker's percentage 計算器（Foodgeek calculator 等） | 算得準 | 算完就結束，沒有世界觀，數字不會變成理解 |
| **「圖書館」— 食譜資料庫/社群** | 愛料理 iCook、下廚房、King Arthur 網站 | 食譜多到找不完 | 只能一篇一篇看，永遠看不見「麵包世界的全貌」 |
| **「抽屜」— 食譜管理 app** | Paprika、Crouton | 收納自己的食譜 | 只是存起來，不比較、不定位、不視覺化 |
| **「手帳」— DIY 筆記/試算表** | Notion、Excel | 完全自由 | 零結構，所有計算和圖都要自己來 |

Breadverse 不屬於以上任何一格：它是**「星圖」**——把每份食譜算成座標，放進同一個宇宙裡看。

### 受眾分析 TA analysis

（各類別一張代表圖 → 圖從缺，附文字說明）

| 受眾 | 說明 | 優先序 |
|---|---|---|
| **健康導向的自烤者**（＝作者本人，第一 TA） | 想吃麵包但不想吃市售高糖油麵包；市售健康麵包又貴。在意豐富度低、長發酵、酸種（低GI、好消化） | ★ 產品為她而做 |
| **精進型烘焙愛好者** | 已經會烤，追求理解與掌控——含水量、發酵、麵筋是他們的語言 | 次要，自然吸引 |
| **好奇的初學者** | 想知道「我做的這個，算是什麼麵包？」——星空給他座標感 | 次要 |
| **社群分享者** | 想秀自己的食譜宇宙 | 從缺——社群功能明確列為「someday, lowest priority」 |

### 價格帶與品牌分析 price zone & brands analysis

**不適用（目前）**——免費個人專案，無定價、無變現計畫。
若日後需要：同類數位工具的價格帶為「免費（廣告/陽春）→ 訂閱 US$2–5/月（Paprika 買斷 US$4.99 可參照）」，
Breadverse 的目標區間會落在**免費**——因為它的目的是存在，不是營收。

### 基本特點 features

- [x] 烘焙百分比即時計算
- [x] **真實含水量**（牛奶/蛋/奶油的水分都算，非天真百分比）
- [x] 五維座標系（含水量、豐富度、穀物結構、發酵時間、麵筋發展）
- [x] 2D 雷達圖 + 經典麵包疊圖比對
- [x] 3D 星系地圖（自由旋轉、五軸任選三軸）
- [x] 經典麵包參照點（法棍、佛卡夏、布里歐修⋯）
- [x] 本地儲存、免註冊（localStorage）
- [ ] 個人觀點濾鏡「健康派」preset（規劃中，issue #7）
- [ ] 食譜版本記錄/烘焙日誌（規劃中，issue #12）
- [ ] 3D 星空深色模式（規劃中，issue #11）
- [ ] 雲端同步／社群分享（明確不做，someday）

### 感受盲測 blind test

**從缺**——尚無外部受測者。目前僅有作者本人的實際使用回饋（已轉成 issues #1–#4：座標原點、縮放、軸標籤、預設視角）。

### 直覺調查 intuition research

**從缺**——尚未進行。預定第一題：把 3D 星空拿給沒看過的人，問「你覺得這是什麼？」——答案若不含「麵包」也沒關係，含「星星/宇宙」就算及格。

### 偏見調查 stereotype research

**從缺**（未正式調查），但產品切入點本身就建立在兩個待驗證的偏見上：
- 「健康麵包＝難吃、乾、貴」→ Breadverse 想證明健康麵包是一整片值得探索的星域
- 「烘焙 app＝廚房白＋溫馨手作風」→ 側翼機會：走天文館的深藍夜空風（見 hero image）

## 3區 — 產品內容

（依框架標示「暫時不需要做」，以下僅留骨架與現有素材）

### uniqueness（150字內）

市場細分下，「秤」求準、「圖書館」求多、「抽屜」求存——全都把食譜當**清單**。
Breadverse 是唯一把食譜變成**空間座標**的：五維計算引擎（含真實含水量）＋ 3D 星系，
讓「這顆麵包是什麼樣的存在」變成一眼可見的位置，而不是一串數字。獨特性不在功能多，
在世界觀：每顆麵包都有它的位置。

### wow factor（2張圖，150字內）

圖從缺。兩個哇點：
1. **旋轉的麵包宇宙**——換一組軸，整個宇宙重新排列，你的吐司和布里歐修的距離忽遠忽近。
2. **變暗而非消失的濾鏡**——套上「健康派」觀點，高糖油的星星暗下去但仍在宇宙中。
   不評判，只聚焦。（規劃中，issue #7）

### functionality（4張圖，300字內）

圖從缺。四個支撐功能（不喧賓奪主）：即時烘焙百分比表／真實含水量計算／雷達圖疊經典麵包比對／免註冊本地儲存。

### buying decision（2張圖，150字內）

免費產品，「買」＝採用。理由呼應高概念：**新價值**——你第一次能看見自己所有烘焙的全貌與軌跡，
以及自己在整個麵包世界中的位置。不是因為它算得比別人準。

### product details（4張圖，100字內）

**從缺**——依賴直覺調查與感受盲測的結果，兩者皆未進行。

資管大二學生，為了「想吃麵包又不想吃高糖油麵包」開始自己烤，為了理解自己烤的東西開始寫這個 app，

### 常見問與答

- **Q：我的食譜會被上傳嗎？** 不會，資料只存在你自己的瀏覽器裡。
- **Q：五個維度是怎麼算的？** 三個由食材克數推導（含水量、豐富度、穀物結構），兩個由你記錄的製法而來（發酵時間、麵筋發展）——因為後兩者本來就不是秤重能算出來的。
- **Q：它會告訴我哪種麵包比較好嗎？** 不會。每顆星都有它的位置，濾鏡只是你選擇看見的視野。
