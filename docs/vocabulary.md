# 詞彙表

八張卡（BV-001 ~ BV-008）裡所有 `outcome` / `technique` 端點的收斂結果。
裁決規則見 `.claude/skills/bread-vocab/SKILL.md`，端點的形狀見 `docs/edge-schema.md`。

## 怎麼讀這張表

- `id` 給機器，`label` 給人，`aka` 是同一顆星在各張卡上的實際寫法。**卡片一個字都不用改**——
  這張表的工作是告訴機器「這些寫法指向同一顆星」，不是要求卡片統一用字。
- `refs` 是哪幾張卡碰過這顆星。**`refs` 只有一筆的，就是目前連不出去的孤星。**
- `狀態` 欄：
  - **已連** — 這顆星目前是某條 `--` 邊的端點，圖上真的存在
  - **只在 L3/L5** — 卡片寫了，但沒有任何一條邊指向它。**它還不在圖上**
- `tags` 是多對多的分群，**刻意不用階層**（理由見第五節裁決 3）。這張表是平的。
- 第五節是**裁決紀錄**：五筆需要人拍板的合併，連背景、反例和理由一起留著，
  免得下次重吵一次。五筆已於 2026-07-22 全數定案。

## 二、結果 `kind: outcome`

### 氣孔——這裡是最大的一筆合併

八張卡有六種寫法：`不規則大氣孔`(BV-001)、`大而不規則的氣孔`(BV-004)、`氣孔開放`(BV-005)、
`內部氣孔中等`(BV-008)、`氣孔中等偏不規則`(BV-006)、`空洞`(BV-003)。

照 **R2（複合描述要拆到單一來源）**，「大而不規則」其實是兩件事：**大小**和**規則度**。
不拆的話，`大而不規則的氣孔` 跟 `氣孔中等偏不規則` 永遠是兩顆星，明明它們有一半是同一件事。
拆完之後每張卡在兩根連續體上各站一個位置，六種寫法收成**兩顆星**。

```yaml
- id: 氣孔大小
  kind: outcome
  polarity: quality
  label: 氣孔大小
  aka: [大氣孔, 大而不規則的氣孔, 氣孔開放, 內部氣孔中等, 氣孔中等, 綿密]
  note: 連續體（細密 ↔ 大）。由麵團延展性與保氣力決定。
        **`綿密`(BV-002) 收在細的那一端**，沒有併進 `絲狀組織`——見第五節裁決 1
  refs: [BV-001, BV-002, BV-004, BV-005, BV-006, BV-008]
  狀態: 已連（BV-001、BV-004 各有一條邊指過來）

- id: 氣孔規則度
  kind: outcome
  polarity: quality
  label: 氣孔規則度
  aka: [不規則, 不規則大氣孔, 氣孔中等偏不規則]
  note: 連續體（均勻 ↔ 不規則）。跟大小是兩件獨立的事——布里歐是「小而均勻」，
        巧巴達是「大而不規則」，但也存在「大而均勻」（吐司）
  refs: [BV-001, BV-004, BV-006]
  狀態: 已連
```

**`空洞` 不併進來。** 照 **R6**，師傅的「製品缺陷」清單跟「品質特性」是兩套東西，
而且機制不同：氣孔是發酵產氣撐出來的，空洞是結構垮掉留下的洞。

```yaml
- id: 空洞
  kind: outcome
  polarity: defect          # ← 唯一一個 defect
  label: 空洞
  note: 結構失敗留下的大洞，不是發酵撐出來的氣孔。BV-003 的失敗模式
  refs: [BV-003]
  狀態: 已連
```

> ⚠️ `polarity: defect` **不是扣分**。星圖上絕對不要把它畫成負值——
> 它描述的是麵包，不是做麵包的人（見 `docs/pattern-language.md` P6）。

### 殼——同樣要拆兩根

六種寫法：`薄脆殼`(BV-001)、`殼薄脆但比法棍軟`(BV-004)、`殼脆`(BV-005)、
`殼薄而軟不脆`(BV-008)、`殼厚`(BV-006)、`外酥內軟`(BV-007)。

`殼薄而軟不脆` 這個寫法自己就證明了要拆：**薄**和**脆**在佛卡夏身上是分開的。

```yaml
- id: 殼厚度
  kind: outcome
  polarity: quality
  label: 殼厚度
  aka: [薄殼, 殼薄, 殼厚]
  refs: [BV-001, BV-004, BV-006, BV-008]
  狀態: 只在 L3

- id: 殼脆度
  kind: outcome
  polarity: quality
  label: 殼脆度
  aka: [脆殼, 殼脆, 酥, 外酥, 軟不脆]
  note: 連續體（軟 ↔ 脆）。跟厚度獨立：佛卡夏薄而軟，酸種厚而脆
  refs: [BV-001, BV-004, BV-005, BV-006, BV-007, BV-008]
  狀態: 已連（BV-008 的「表面淋的油 → 殼薄而軟不脆」）
```

### 老化——這裡有一個容易做錯的合併

skill 的 R5 直接點名這顆星（「老化快跟放得久＝一顆 `老化速度`」），照做：

```yaml
- id: 老化速度
  kind: outcome
  polarity: quality
  label: 老化速度
  aka: [老化快, 24 小時後結束, 放得久, 耐放, 保存性]
  note: 澱粉老化（retrogradation）。**兩張卡用兩種完全不同的機制抵抗它**——
        BV-002/BV-003 靠油鎖水，BV-006 靠酸抑菌（pH 4.2–4.4）。
        機制不同但結果同一顆星，這正是圖才看得出來的東西
  refs: [BV-001, BV-002, BV-003, BV-006]
  狀態: 已連（BV-001「沒有油鎖水 → 老化快」、BV-006「酸 → 放得久」）
```

**這是全表最有價值的一筆。** 合併之前，法棍的「24 小時就不行」和酸種的「放得久」是
兩顆不相干的星；合併之後它們是同一根連續體的兩端，**一條完整的星座線就出現了**。

**但可頌的「很快就軟掉」不能併進來。**

```yaml
- id: 酥脆保持
  kind: outcome
  polarity: quality
  label: 酥脆保持
  aka: [很快就軟掉, 酥脆撐不過幾小時]
  note: **機制不同，所以不是老化速度。** 澱粉老化是麵包心的事；
        殼回軟是水氣從內部跑到殼上（moisture migration）。
        照 R1 判機制不判措辭，這是另一顆星
  refs: [BV-007]
  狀態: 只在 L3
```

> 這一筆是全表最容易搞錯的地方。「放不久」聽起來是同一件事，
> 但師傅眼裡**法棍隔夜變硬**和**可頌兩小時變軟**是相反方向的兩個問題。

## 三、手法 `kind: technique`

### 油脂位置——這批卡片最重要的三顆星

BV-002 / BV-007 / BV-008 撞出來的發現：**豐富度軸只記油有多少，不記油在哪裡，
而決定後果的是後者。** 三個位置是三顆獨立的星，不是一根連續體，所以不合併。

```yaml
- id: 油混入麵團
  kind: technique
  label: 揉進麵團的油
  aka: [油混進麵團, 油包澱粉, 油膜包住麵筋蛋白]
  note: 唯一會 shorten 麵筋的位置。**布里歐那條標成 hard 的邊，前提就是這顆星**
  refs: [BV-002, BV-003, BV-008]
  狀態: 已連

- id: 層壓
  kind: technique
  label: 層壓
  aka: [油以冷的整塊夾在層間, lamination]
  note: 油量比 BV-002 還多，麵筋卻更高——因為油從頭到尾沒碰到麵筋
  refs: [BV-007]
  狀態: 已連

- id: 表面淋油
  kind: technique
  label: 表面淋的油
  note: 完全不參與麵筋，只作用在殼跟外觀
  refs: [BV-008]
  狀態: 已連
```

### 預發酵種——三顆平的星，用 `tags` 串起來

三者都是「預先培養的種」，但**菌相和含水量都不同**（商業酵母 vs 野生菌、硬種 vs 液種），
所以不合併。但它們確實同屬一類，需要一條線把三張卡接起來。

**裁決（2026-07-22）：用 `tags` 而不是上位節點。** 詞彙表維持平的——
`tags` 讓「找出所有用預發酵種的麵包」照樣查得到，但不承諾一個階層。理由見第五節裁決 3。

```yaml
- id: biga
  kind: technique
  label: biga
  aka: [義式硬種]
  tags: [預發酵種]
  note: 含水 50–60%，商業酵母。比 poolish 硬
  refs: [BV-004]
  狀態: 已連

- id: lievito-madre
  kind: technique
  label: lievito madre
  aka: [pasta madre]
  tags: [預發酵種, 天然酵種]
  note: id 用義大利部長令的用字（R4：法規 ＞ 業界 ＞ 個人）。
        極硬、管理極嚴（每天餵、開工前 3 次續種）
  refs: [BV-003]
  狀態: 已連

- id: levain
  kind: technique
  label: levain
  aka: [天然酵種, 酸種]
  tags: [預發酵種, 天然酵種]
  refs: [BV-006]
  狀態: 已連
```

> `tags` 是這張表第一個**多對多**的欄位：`lievito-madre` 同時掛兩個標籤，
> 而換成上位節點就得逼它選一個父節點。**這是刻意不建樹的理由。**

### 手法（L4 與 L5 已照 R3 合併）

L5 那句話變成邊上的 skill cost（#22），不是新節點。

  note: 五張卡的 L5 都在講它。**目前為止最貴的一顆星**——

  note: 原寫法「只能靠摺疊與時間」是複合的，照 R2 拆成 `摺疊` + `長時間發酵`

  狀態: 已連（在 BV-001 的複合端點裡，見下）

## 五、五筆裁決紀錄（2026-07-22 定案）

留背景不留結論會讓下次重吵一次，所以理由跟反例都寫在這裡。

### ✅ 1. `綿密` 不併進 `絲狀組織`，改收在 `氣孔大小` 的細端

**兩個詞在講什麼**：`綿密` 看的是**洞有多小多勻**（切面像海綿蛋糕）；
`撕得出絲` 看的是**它怎麼斷**（用拉的會拉出一條條的絲，像起司條）。

**合併的理由**（不成立）：兩個都出現在高油麵包上，都能歸因到「油脂把麵筋撐成薄膜」。

**決定性的反例——兩個方向都有：**

| | 綿密 | 撕得出絲 |
|---|---|---|
| 布里歐 | ✅ | ✅ |
| **潘娜朵尼** | ❌ **孔又大又長** | ✅ **絲最強** |
| 無油白吐司 | ✅ | ❌ 撕開是鬆的 |

潘娜朵尼那一行是關鍵：**它一點都不綿密，卻是拉絲最強的。** 兩者可各自單獨存在 → 兩顆星。

### ✅ 2. `極輕` 另開一顆 `輕盈度`，不跟 `嚼感` 併成一根連續體

**兩個詞在講什麼**：`輕盈度` 是用**手**量的（同樣大小拿起來多重，即比容積）；
`嚼感` 是用**牙齒**量的（咬下去回推的力道，來自麵筋彈性）。

**合併的理由**（不成立）：直覺上「輕 ↔ 紮實有嚼勁」像一根桿子的兩端，R5 會想這樣判。

**決定性的反例：**

| | 輕 | 嚼 |
|---|---|---|
| 貝果 | ❌ 紮實 | ✅ |
| 潘娜朵尼 | ✅ 極輕 | ❌ 入口就化 |
| **巧巴達** | ✅ **大氣孔，很輕** | ✅ **很嚼** |

**巧巴達同時站在兩端** → 不可能是同一根桿子。它做得到是因為「裡面有多少空氣」
和「麵筋有多強」本來就是兩個獨立的量。

### ✅ 3. 預發酵種用 `tags`，不加上位節點

三個選項比較過：

| | 做法 | 代價 |
|---|---|---|
| A | 不處理 | 「三張卡都用了預發酵種」這條線永遠畫不出來 |
| B | 加上位節點 `預發酵種` | **詞彙表從此有階層**，每個新詞都要回答「上層是誰」 |
| **C ✅** | 貼 `tags: [預發酵種]` | 表維持平的，查詢照樣做得到 |

**選 C 的理由：階層是很難守的承諾。** 麵包的分類本來就不是乾淨的樹——
`lievito-madre` 同時是「預發酵種」也是「天然酵種」，換成上位節點就得逼它選一個父節點。
`tags` 是多對多的，加得掉也拿得掉，不改變表的形狀。

> ⚠️ 這條的效力超出預發酵種：**這張表刻意是平的。** 之後想分群一律先考慮 `tags`。

### ✅ 4. `加油時機` 不併進 `油混入麵團`——機制歸機制，對策歸對策

**背景**：布里歐的奶油多到一開始全丟進去麵筋就永遠出不來——油會搶先包住麵粉蛋白，
蛋白就連不起來。所以做法是先把麵筋打出來，**確認夠強了才分次加冰奶油**。

- L4 的 `油混入麵團` 是**機制**：油在麵團裡會擋住麵筋連結。這是物理，沒人做麵包它也成立。
- L5 的 `加油時機` 是**對策**：所以等麵筋出來再加。這是人的選擇。

問題等於「下雨」跟「帶傘」算不算同一件事。R3 說「要用它」和「它很難」是一顆星，
但那是同一件事的兩層引用；**機制和對抗機制的手法不是。**

**決定性的理由：#22 要把成本掛在星星上算難度，而物理是不用付錢的。**
「油會 shorten 麵筋」不花你任何力氣，花力氣的是「分次加冰奶油」這個動作。
合併會把成本掛到一顆不該有成本的星上。

> 這條同時定下 R3 的邊界：**R3 只合併「同一件事的不同引用層」，不合併「因與對策」。**

### ✅ 5. `#麵筋 的「達成成本」↑` 先擱著，不為它開星

BV-002 有一條邊指向它，但它**不是一顆星**——它是「`#麵筋` 這顆星的取得成本上升」，
也就是 #22 講的 cost。現在的 schema 沒地方放成本，所以它被硬寫成假節點。

**處置**：等 #22 落地，那條邊改寫成「指向 `麵筋強度`，邊上帶 `cost: {skill: +}`」。
在那之前不動它，**也不要為它開一顆星**——開了之後就很難拆掉。

## 六、這張表暴露的三件事

### 1. 目前的圖有一半是斷的

24 顆 outcome 星裡，**只有 9 顆真的被某條邊指到**，其餘 15 顆只活在 L3 的散文裡。
換句話說——**卡片寫了結果，但沒寫「什麼造成了這個結果」**。

最明顯的：`乳脂香`、`蛋黃香`、`麥香`、`橄欖油香`、`堅果調` 五顆風味星，
**沒有任何一條邊指向它們**。可是每一顆的成因都是已知的（乳脂、卵黃、裸麥、橄欖油、
沒有別的味道遮）。**這五條邊只是還沒寫，不是不存在。**

### 2. 收斂本身就生出了新的星座線

合併之前看不到、合併之後才出現的跨卡片連線：

- `老化速度` 一顆星串起 **BV-001 / BV-002 / BV-003 / BV-006**，而且兩種抗老化機制
  （油鎖水 vs 酸抑菌）是對照組
- `整形` 一顆星串起 **五張卡**，全部出現在 L5 —— 它會是 #22 難度計算裡最貴的節點
- `蒸氣` 把 BV-001 的複合端點跟 BV-005 的鑄鐵鍋接上了（**兩張卡在解同一個問題**）
- `氣孔大小` / `氣孔規則度` 拆開後串起五張卡

### 3. 有兩個端點根本不該是節點

- `12–18 小時`（BV-005）是一個**值**
- `#麵筋 的「達成成本」↑`（BV-002）是一個**成本**

兩個都是因為 `edge-schema.md` 沒有地方放它們，才被硬塞成端點。
加上可頌逼出來的「這條邊的前提」（見 `docs/cards/可頌.md`），
**edge schema 現在缺三個欄位：`cost`、`value`、`precondition`。** → #22 / #23
