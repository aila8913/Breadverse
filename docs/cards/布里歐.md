# 布里歐 Brioche

`BV-002` · France · viennoiserie

## L1 命名 #命名/故事  //故事最不重要，放到最後。但是可以完整，無須簡約

「讓他們吃布里歐吧」不是瑪麗·安東妮說的。盧梭《懺悔錄》1765 年寫，那年她 9 歲、人在奧地利。原文只說「一位偉大的公主」，沒指名。第一個栽贓的是 Alphonse Karr，1841 年，她死後 48 年。

**法棍靠法律定義，它靠故事定義——而且是假的。命名層不需要是真的，只需要黏得住。** //不需要，因為每張卡片是獨立的，除非麵包之間有強相關(可能同樣歷史背景、有錢和沒錢)

## L2 座標

範圍寬度 ＝ 模糊空間。**它的模糊空間有官方名字。**

| 軸 | 程度 | 範圍 | 註解 |
|---|---|---|---|
| 含水量 | #含水量/中低 | `50–60` | 看起來乾，其實水的工作被蛋和奶油接手了 |
| 豐富度 | #豐富度/中→極高 | `25–95` | **寬度大到誇張。** pauvre 20–25% 奶油／moyenne 40–50%／riche 70–100% ——三個都叫布里歐 |
| 麥種結構 | #麥種/高 | `90–100` | 跟法棍同一個點 |
| 發酵時間 | #發酵/低 | `15–30` | 不是你選的，是油決定的 ↓  //下面的勾稽可能可以直接放這?，不用用自然語言寫，這是想要給系統看的參數 #油 (up) -- #發酵時間 (down)|
| 麵筋擴展 | #麵筋/極高 | `90–100` | 值很高，但**成本**更高 ↓ |

## L4 勾稽

```
#豐富度/高 -- 油包澱粉 → 澱粉酶構不到 → 分解不出糖 → 酵母沒飯吃 -- #發酵/低  //會用符號語言呈現是希望給系統更好的讀取資料，因為我在想這種多為多關係的資料結構應該要怎麼做，有沒有相似的方法可以參考
              （你自己填的 90 和 20，自己印證了這條四段鏈）

#豐富度/高 -- 油 shorten 麵筋 -- #麵筋 的「達成成本」↑
              （Modernist：enriched doughs might take longer to knead）
              ※ 注意：它拉高的不是值，是代價。布里歐的麵筋照樣到 95，只是要揉更久

#豐富度/高 + #糖 + #蛋 -- 上色快到不像話 -- 爐溫必須反向調低  //#上色 (up) #烘焙溫度 (down)
              （Hamelman。布里歐的金色是「多」出來的，法棍的褐色是「省」出來的）
```

## L3 結果

綿密、撕得出絲、奶香、金黃。**放得久**——油鎖住了水，正好是法棍失去的那樣東西。

## L5 手

```
! 奶油要冷、要分次加
! 麵筋要先出來才能加油 —— 油先進去就先包住麵粉，麵筋永遠出不來
  ↑ 這條是「順序」。一模一樣的參數，不同順序，做出不同的麵包
```
