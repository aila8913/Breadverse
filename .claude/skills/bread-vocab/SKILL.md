# 詞彙裁決

## 這個 skill 在解什麼問題

Breadverse 的卡片邊有四種端點（見 `docs/edge-schema.md`）：`axis` / `bread` / `outcome` /
`technique`。前兩種有 id，後兩種目前是純文字——**而那正是跨卡片的邊最需要接上的地方。**

如果法棍寫「不規則大氣孔」、巧巴達寫「大而不規則的氣孔」，對圖來說是兩個節點，兩顆星永遠連不
起來。星座（#19）不是死在欄位不夠，是死在這裡。

所以每次寫新卡片，都會冒出一批「這個詞表裡有了嗎？算同一個嗎？」。這個 skill 是那個判斷的準則。

## 立場：業界師傅怎麼分

一般人依**感覺像不像**分類，師傅依**做法一不一樣**分類。這是唯一重要的差別。

> 「絲狀」跟「撕得出絲」聽起來是兩個詞，但麵包師傅眼裡是同一件事：麵筋薄膜被油脂分隔。
> 只是布里歐做到 7 分、潘娜朵尼做到 10 分。**強度差不是種類差。**

反過來：「奶香」跟「蛋黃香」聽起來都是「香」，師傅眼裡是兩個東西，因為**來源不同**——一個來自
乳脂，一個來自卵黃。做法上是兩個獨立的鈕。

**判準一句話：能不能追到同一個製程原理？可以就合併，不行就分開。**

## 七條規則

依序套用，第一條打中就停。

### R1 依機制合併，不依措辭
兩個描述追到同一個物理／化學原理 → **同一顆星**，強度差交給軸的數值去表達。
> 撕得出絲 ＝ 絲狀撕裂 ＝ 絲狀組織（麵筋薄膜被油脂分隔）

### R2 複合描述要拆到單一來源
「奶油蛋黃香」「高溫＋蒸氣＋長發酵殘糖」這種一格塞多件事的，**先拆再編號**。
理由是複合詞**永遠不會跟別的卡合併**——只有拆到原子，跨卡片的邊才連得起來。
> 奶油蛋黃香 → `乳脂香` + `蛋黃香`（潘娜朵尼同時指向兩顆）

### R3 「要用它」跟「它很難」是同一顆星
同一件事出現在 L4（前提／因果）和 L5（手），**不是兩顆星，是一顆星被兩層引用。**
L4 說「需要它」，L5 說「它難在哪」。難度是 #22 掛在邊上的 `cost`，不是新節點。
> 蒸氣（L4 條件）＋ 蒸氣時機（L5 手感）＝ 一顆 `蒸氣`，L5 那句變成邊上的 skill cost

### R4 id 用正式名，label 用你的用字
`id` 給機器，取**最穩定**的名字，優先序：法規用字 ＞ 業界通用 ＞ 你的用字。
`label` 給人看，**照你原本怎麼寫就怎麼寫**。別名進 `aka`。
> id: `lievito-madre`（義大利部長令的用字）· aka: `pasta madre` · label 照卡片走

**這條是刻意設計的**：讓機器拿到穩定的把手，同時一個字都不改你的語氣。

### R5 連續現象是一顆星，兩端是值
同一個過程的兩端，**不要開兩顆星**——開兩顆的話它們永遠是兩個不相干的節點，
還要另外手寫一條「相反」邊去救。一顆星才連得起來。
> 老化快（法棍）跟 放得久（布里歐、潘娜朵尼）＝ 一顆 `老化速度`，兩張卡站兩端

### R6 缺陷跟特性分成兩種 kind
師傅有一套獨立的「製品缺陷」清單（空洞、腰折、裂），跟「品質特性」不混在一起。
outcome 帶 `polarity: quality | defect`。
> 空洞 是 defect；薄脆殼 是 quality

⚠️ **這不違反「app 沒有 fail state」**（見 `docs/pattern-language.md` P6）。
缺陷描述的是**麵包**，不是**做麵包的人**。「這個做法會做出空洞」是知識；
「你做不好」是評分。這個 skill 只做前者，星圖上也絕不要把 defect 畫成扣分。

### R7 拿不定主意時，不要合併
**合併錯了很難救**：兩張卡的邊指向同一顆星之後，就分不出哪條原本是誰的。
**分開錯了很好救**：之後補一條 `aka` 重新指過去就行。
> 不對稱的風險 → 預設不合併

## 產出格式

裁決完寫進 `docs/vocabulary.md`：

```yaml
- id: 老化速度
  kind: outcome
  polarity: quality
  label: 老化速度
  aka: [老化快, 放得久, 保存性]
  note: 澱粉老化。油脂與糖會拖慢它
  refs: [BV-001, BV-002, BV-003]
```

## 三條操作紀律

1. **詞彙表是卡片的副產物，不是前置作業。** 絕對不要坐下來列出「所有麵包可能的結果」——
   那會生出一堆沒有任何邊指向它的死詞。**每一條新詞都必須是被某條邊逼出來的。**
2. **提案，不要代替她決定。** 合併判斷是在決定「她的宇宙裡哪些東西算同一顆星」——
   套完規則之後，把結論**跟理由**一起端出來讓她點頭，不要靜靜合併掉。
   規則有衝突或 R7 說不準時，一定要問。
3. **不要引進機器學習。** 這個表的量級是幾十條，人判斷比較準，而且外部語料訓練出來的 label
   會把她的用字（「空洞」「麥香當主角」）正規化掉——**那個語氣正是產品的價值。**
   等卡片破六十張、開始出現「我忘記三個月前用過什麼詞」的問題時，embedding 才有用，
   而且用途是**建議合併**、她點頭，不是自動決定。
