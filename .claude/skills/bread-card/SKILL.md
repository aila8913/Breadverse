# 寫一張麵包卡片

## 三條不可妥協的原則

### P1 每張卡從一張白紙開始
一張卡只寫**這款麵包自己**。不寫「法棍靠法律、它靠故事」，不寫「它比布里歐那個假故事還年輕」，
不寫「這張卡把前兩張合起來了」。

**理由不是風格，是資料品質。** 寫在卡裡的比較是**作者的框架**，不是證據；一旦寫進去，
它會冒充成一條邊被讀進圖裡。而真正有價值的跨卡片關聯是**收斂之後自己浮出來的**——
`docs/vocabulary.md` 就是證明：沒有人手寫「法棍的蒸氣烤箱和免揉的鑄鐵鍋加蓋是同一件事」，
是端點收斂到 `蒸氣` 這顆星時它自己出現的。**手寫的比較是意見，浮出來的比較是發現。**

例外只有一種：**兩款麵包之間有實質的歷史或製程因果**（同一份法規、同一個發明者、
一個是另一個的變體），且該因果本身有查證來源。這種情況寫成**一條有 reason 的邊**，
不是寫成一句比較句。

### P2 L1 不預設分類，只寫這款麵包的來歷
L1 的任務是：**這個名字從哪來、什麼時候、誰說的、可信度多少。**

- **不要先挑一個 `#命名/xx` 標籤再去填內容。** `#命名/法律`、`#命名/故事`、`#命名/傳說` 這些
  分類是**收斂的產物，不是寫作的大綱**——跟 `bread-vocab` 說「詞彙表是卡片的副產物」同一個道理。
  先挑標籤會讓查證變成找證據支持已選的框，而不是查出事實。
- **不要為了湊出「這款靠什麼定義」這種對仗句而扭曲事實。** 沒有法規就是沒有法規，
  不需要因此改講一個故事來平衡版面。
- 每條歷史主張都要走 `bread-history`，落在 `確證 / 可能 / 流傳但無據 / 已否證` 四級之一，並附最早出處。
- **故事層放最後，但要完整。** 不重要 ≠ 刪掉——它排在後面，不是被簡約掉。

### P3 一款麵包有多種做法 → 開分支卡，不要平均
如果查到的資料**內部彼此矛盾**，先問一句：**這是一個數字有爭議，還是這其實是兩款麵包？**

> **這條規則是被真實的錯誤逼出來的。** `classicBreads.ts` 的佛卡夏是 `hydration: 85`，
> 但傳統熱那亞佛卡夏是 55–65%。85 不是錯誤的估計——它是**另一款麵包**（現代高水改編版）。
> 兩者被平均成一顆星，結果就是這顆星被畫在宇宙裡沒有任何一款佛卡夏存在的位置。
> **平均兩款麵包會做出一款不存在的麵包。**

分支的判準：**做法上出現分歧點**（含水量差一個級距、發酵方式不同、油脂位置不同、
成形或烘烤方式不同）→ 開兩張卡。只是**同一做法的數字微調**（有人 68% 有人 70%）→ 一張卡，
用範圍表達。

分支卡的規格：

- **各自拿獨立的 `BV-xxx` 編號。** 不用 `BV-008a` 這種子編號——子編號預設了誰是正統，
  那是還沒查證就先做的判斷。變體卡是完整的一張卡，不是附錄。
- 檔名與標題**明確標出是哪一款**：`佛卡夏（熱那亞）.md`、`佛卡夏（台灣版）.md`。
- 用 `family:` 欄位標記同宗（`family: 佛卡夏`），**用 tag 不用上位節點**——
  沿用 `docs/vocabulary.md` 的既定先例（階層是很難守的承諾）。
- 兩張卡之間的關係寫成**一條帶 reason 的邊**（誰從誰來、什麼時候、依據是什麼），
  而且那條邊本身要有來源。查不到就不要寫。

## 三段式流程

**寫卡片一律開新的 agent 做，不要在主 session 裡邊聊邊寫。** 主 session 已經讀過別張卡，
會不自覺把比較和既有框架帶進去——那正是 P1 要防的東西。

### 第 1 段：查證並書寫（新的 `general-purpose` agent）

⚠️ **必須用有網路的 agent。`sonnet-engineer` 沒有網路存取**，不可能自己查證，
把查證工作交給它只會得到看起來很像真的內容。

給這個 agent 的東西：
- 麵包名稱、要拿的 `BV-xxx` 編號
- **卡片格式範本**（層級結構與標記法，見下）
- `bread-history` 的查證標準
- **不要給它其他卡片的內容。** 給了就違反 P1——它會開始比較。
  需要參考格式的話，給格式說明，不要給整張別的卡。

要求它交出來的東西：
- 完整卡片
- **每個數字、每條歷史主張逐條標來源**（不是文末列一串連結了事）
- 一份「查不到 / 來源互相矛盾」的清單——**矛盾清單是 P3 的觸發器**，不能省

### 第 2 段：獨立審查（另一個**全新**的 agent）

**關鍵：審查的 agent 不要先看第 1 段的來源清單。** 先給它卡片本體，要它**自己重查**主張，
再對照來源清單。順序反過來就只是在確認別人的作業，不是審查。

審查清單：

1. **歷史主張**：每一條都走 `bread-history` 的六種失效模式，確認信心等級標得對。
2. **數字**：每個座標範圍是否追得到 A/B 級來源；配方是否換算成 baker's %（並註明分母是否含
   preferment 裡的粉）。**不准從 `classicBreads.ts` 抄——那些是手估值，不是資料。**
3. **端點污染**：邊的端點必須是**原子的詞**，不是整句話。
   「油以冷的整塊夾在層間」是一句話，不是節點。（PR #28 抓到四處。）
4. **P1 違規**：全文搜有沒有提到別款麵包的名字。有的話，除非它是一條有來源的實質因果邊，
   否則刪掉。
5. **P3 觸發**：矛盾清單裡有沒有東西其實是「這是兩款麵包」。
6. **軸的破洞**：卡片撞出來的模型問題要標出來，但**寫成觀察，不是寫成對別張卡的評論**。

審查 agent **只回報，不直接改**。改動回到主 session 或第 1 段的 agent 手上。

### 第 3 段：收斂詞彙（`bread-vocab`）

卡片定稿後，把新的 `outcome` / `technique` 端點拿去跑 `bread-vocab` 的七條規則，
併進 `docs/vocabulary.md`。

**這一段是跨卡片關聯唯一該發生的地方。** 前兩段刻意讓每張卡各寫各的、用字各自為政，
到這裡才對齊——所以浮出來的連結是資料本身的，不是誰寫進去的。

## 卡片格式

沿用既有的五層結構與標記法（她自己設計的，不要改）：

- `L1 命名` — 來歷與名字。走 `bread-history`，帶信心等級
- `L2 座標` — 五軸的**範圍**（不是點；**範圍寬度本身就是資訊**，表達的是這款麵包的模糊空間）
- `L3 結果` — 吃起來、看起來是什麼
- `L4 因果／前提` — 邊。`--` 連結，`+` 表示多源（hyperedge），見 `docs/edge-schema.md`
- `L5 手` — `!` 標記的手感知識、難的地方

標記法：`#軸/程度` 標籤搭配註解裡的確切數字；每張卡底部列來源。

## 卡片裡不准出現的兩種東西

**這兩條是她逐張卡標出來的，違反的話等於把答案先算好塞進輸入。**

### N1 濾鏡不寫在卡片裡
不要寫「在你的濾鏡下它暗到底」這種段落。**濾鏡是 app 對資料做的運算，不是資料本身。**
寫進卡片就等於這張卡永遠只有一種觀點——之後想加第二種（#22 的難度濾鏡「我今天只有 2 小時」）
時，卡片裡手寫的判斷會跟新濾鏡打架。

**卡片存座標，濾鏡自己算亮暗。**

### N2 專案層級的發現不寫在卡片裡，開 issue
卡片撞出模型的洞（軸算錯、schema 少欄位、某個假設被推翻）是**很有價值的產出**，
但它屬於 backlog，不屬於資料。寫成 issue，卡片裡不留。

> 反例：BV-003 原本有整段「你的 `computeFermentationTime` 100 封頂」的分析。
> 那是 issue #16 的內容，不是潘娜朵尼的性質。

## L1 的篇幅：短
她對 BV-003 那份 65 行、附拉丁原文與公報條號的 L1 的原話是
**「其他我大概都沒興趣看下去」**。她唯一挑出來說有興趣的那句，是 1814 年字典的釋義
「用奶油、糖和葡萄乾裝點的一種麵包」——**具體、感官、想像得出來的東西。**

所以：

- **查證要做滿，寫出來要短。** 查證的功夫花在確保沒寫錯，不是花在展示過程。
  年份、原文、條號這些留在來源清單裡，正文不要背書目。
- **故事是選配，而且門檻在 `確證`。** 她的原話：「不一定要加故事和特色，有就加，沒有也沒差。」
  ⚠️ **只能標到 `流傳但無據` 的故事，預設直接刪掉，不要留。**
  她看到「收在這裡是因為好聽，不是因為可信」的當下反應是「**那就刪掉**」——
  一個自己承認不可信的段落，對她沒有價值，對圖更沒有。**留下來的門檻是查得到，不是好聽。**
  相對的，**「特色」（材料、吃法、保存）是查得到的事實，可以留**——那不是故事。
- **不要動不動就提法律。** 除非這款麵包是**以法規聞名**的那種（法棍的 Décret Pain 級別），
  否則不要在 L2 的註解裡寫「法律沒規定，物理規定」這種句子。留一句非講不可的就好。

## 三條寫作要求

### W1 每個步驟都要有時間標籤
> 「時機對麵包來說幾乎是最重要的之一」

L5 的每一條都要標**什麼時候做**，不能只寫做什麼。用具體的時間錨點：

```
! 出爐後 0 分鐘：立刻用長籤穿過底部 2 cm 處
! 出爐後數小時：倒吊到完全放涼才能翻正
```

而不是「出爐立刻穿籤、倒吊好幾小時」——後者讀者得自己拆出時間軸。

### W2 主詞要明確
「至少 3 天」——**什麼東西 3 天？** 寫「**發酵**至少 3 天」。
「每天餵、養好幾年」——**到底是天還是年？** 寫清楚「每天」是頻率、「好幾年」是壽命。

### W3 因果用「因為…所以…」直接講
不要寫「差別不在配方，在要不要跟物理談判」這種漂亮但要讀者自己解碼的句子。
先講機制，再講結果：

> **因為**又油又甜的麵團會同時餓死酵母、又抽乾酵母，**所以** panettone 沒辦法只靠配方解決，
> 它得付出下面這一整串代價。

語氣可以有個性，**但因果鏈不要藏在修辭裡**。

### W4 用卡片自己的記法，不要用後設散文
不要寫「這條之所以留著，是因為 L4 的整串代價都是它逼出來的」——那是**在跟讀者解釋編輯決定**，
不是資料。卡片已經有連結記法，直接指過去：

```
**法規**：要叫 panettone 就必須用天然酵種 -- L4
```

一行、可讀、而且 `--` 是機器讀得到的邊。**凡是能用記法表達的，就不要用句子解釋。**

### W5 數值用真實單位，不要用正規化分數
發酵時間寫 `72–120 小時`，不要寫 `100`。**正規化是顯示層的事**，卡片是資料，資料存真值。
（她的原話：「那就不要是 1~100，直接用時間來算 ex. 24hr」→ issue #16）

## 一句話總結

> **查證要獨立，書寫要獨立，審查要獨立——只有收斂那一步該把卡片放在一起看。**
